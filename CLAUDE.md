## Что это за проект

**YouTube Trends** — ежедневный дашборд динамики и трендов по карточкам видео в
разрезе авторов и тем, плюс карта связей идей между видео в стиле Obsidian.

Источник данных — приватный репозиторий **`bugoll/MyCrabs`**, папка
`youtube-daily`, файлы с подстрокой `daily_package` в имени (форматы `.json` и
`.md`). Их нужно ежедневно копировать сюда, парсить, накапливать историю метрик
и пересобирать датасеты дашборда и графа.

## Текущий статус: рабочий MVP ✅

Готово и проверено (Python компилируется, пайплайн прогоняется, JS проходит
`node --check`):

- Парсинг `.json` + `.md` со слиянием по `(video_id, дата)`.
- Накопление истории метрик, агрегаты по авторам/темам, таймлайн, тренды.
- Семантические связи идей (sentence-transformers) с fallback на TF-IDF.
- Статический дашборд (карточки, авторы, темы) + force-граф на canvas.
- GitHub Actions: ежедневный запуск + публикация на Pages.
- Демо-данные в `data/raw/` (6 видео, 3 автора, 3 темы, 2 дня замеров).

## Архитектура и поток данных

```
MyCrabs/youtube-daily/*daily_package*.{json,md}
  → scripts/fetch_packages.py   клонирует MyCrabs по PAT, копирует в data/raw/
  → scripts/process.py          парсинг → история → датасеты
      ├─ scripts/lib/normalize.py  .json/.md → единая схема, merge дубликатов
      └─ scripts/lib/embed.py      связи идей (semantic / TF-IDF), пороги по бэкенду
  → docs/data/history.json      временные ряды метрик по каждому видео
  → docs/data/dashboard.json    карточки, авторы, темы, таймлайн, тренды
  → docs/data/graph.json        узлы и рёбра карты связей
  → docs/ (index.html, app.js, graph.js, styles.css)  статический дашборд (Pages)
```

## Как запускать

```bash
pip install -r requirements.txt          # опционально; без этого работает fallback
export MYCRABS_TOKEN=ghp_xxx             # PAT с чтением MyCrabs (для fetch)
python scripts/fetch_packages.py --dest data/raw      # подтянуть свежие пакеты
python scripts/process.py --raw data/raw --out docs/data   # собрать датасеты
python -m http.server -d docs 8000       # посмотреть: http://localhost:8000
```

Переменные окружения: `EMBED_BACKEND=auto|st|tfidf`, `EMBED_MODEL=<hf-модель>`,
`MYCRABS_REPO`, `SOURCE_DIR`, `PACKAGE_GLOB`.

## Конвенции и важные ограничения

- **Ветка разработки**: `claude/intelligent-pascal-laCnA`. Не пушить в другие
  ветки без явного разрешения пользователя. PR создавать только по запросу.
- **Без токенов в коде**: `MYCRABS_TOKEN` берётся из секретов/окружения, никогда
  не коммитится и не логируется.
- **Идемпотентность**: повторный прогон `process.py` за тот же день перезаписывает
  снапшот, а не дублирует его.
- **Graceful fallback**: пайплайн обязан работать даже без сторонних пакетов
  (встроенный TF-IDF на чистом Python). Не ломать это свойство.
- **Пороги похожести зависят от бэкенда** (косинус у плотных и разреженных
  векторов в разных шкалах) — см. `_DEFAULT_THRESHOLD` в `embed.py`.
- **Демо-данные**: файлы `data/raw/2026-06-0*` и `docs/data/history.json` —
  демонстрационные. Когда пойдут реальные пакеты, их нужно удалить, чтобы история
  началась с чистого листа.
- **Стиль**: Python в стиле существующих модулей (типы, docstring'и, без лишних
  зависимостей); фронтенд — vanilla JS без сборщиков, Chart.js с CDN.

## Что можно делать дальше (бэклог)

Если пользователь просит «продолжить проект» — предложи и реализуй из этого
списка (уточни приоритет, если непонятно):

1. **Реальные данные**: настроить секрет `MYCRABS_TOKEN`, включить Pages, прогнать
   `fetch_packages.py` на боевом MyCrabs, удалить демо-данные.
2. **Сверка схемы**: подстроить алиасы полей в `normalize.py` под реальный формат
   `daily_package`, когда он станет известен.
3. **Семантика качественнее**: включить sentence-transformers в CI (уже в
   requirements), при желании добавить LLM-разметку типа связи (Claude API,
   опционально, по ключу `ANTHROPIC_API_KEY`).
4. **Аналитика**: скорость роста (views/день), всплески (аномалии), удержание тем
   во времени, «восходящие» авторы.
5. **Граф**: кластеризация по сообществам, узлы-хабы тем/авторов, фильтр по дате,
   экспорт в формат Obsidian Canvas / JSON Canvas.
6. **Карточки**: миниатюры YouTube, доля вовлечённости, сравнение нескольких видео.
7. **Тесты**: pytest на `normalize.py` (парсинг/merge) и `embed.py` (пороги).
8. **Алерты**: ежедневная сводка (резкий рост/падение) в README-бейдж или issue.

## Файлы, на которые смотреть в первую очередь

- `scripts/lib/normalize.py` — вся логика разбора форматов и слияния.
- `scripts/process.py` — агрегация, история, сборка `dashboard.json`/`graph.json`.
- `scripts/lib/embed.py` — связи идей и выбор бэкенда.
- `docs/app.js` / `docs/graph.js` — рендеринг дашборда и force-графа.
- `.github/workflows/daily.yml` — автоматизация.
- `README.md` — пользовательская документация и настройка.
