#### Key points

- Системы обмена сообщениями выступают посредниками (брокерами), обеспечивающими доставку сообщений даже при недоступности получателя.
- Использование брокеров упрощает масштабирование через балансировку нагрузки, но вводит задержки двойного хопа и создает точку отказа.
- Для асинхронных задач рекомендуется начинать с JSON, переходя к бинарным форматам (Avro/Protobuf) только при необходимости производительности; для последних требуется Schema Registry из-за отсутствия схемы в теле сообщения gRPC.
- RabbitMQ использует модель Exchange -> Queue -> Consumer с поддержкой роутинга и балансировки round-robin. Гарантии доставки At-Least-Once могут приводить к дублированию, требующему обработки на уровне приложения (идемпотентность).
- Kafka представляет собой распределенный реплицируемый лог сообщений без встроенного роутинга; топик содержит упорядоченную последовательность данных в партициях.
- Производитель пишет только в конец партиции (append-only), чтение идет по офсету. Распределение нагрузки зависит от хеширования ключа сообщения на количество партиций.
- Consumer Group объединяет экземпляры приложения для параллельной обработки, но порядок доставки внутри группы не гарантирован между разными топиками.
- Офкеты сохраняются в служебном топике __consumer_offsets с задержкой по умолчанию 5 секунд, что повышает надежность, но может вызывать дублирование при сбоях. Для отказоустойчивости в Kafka нужен replication factor >= 3.
