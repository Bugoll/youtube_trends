#### Key points

- Кэш — это временное хранилище данных для переиспользования результатов дорогостоящих операций без их повторного выполнения.
- Основные цели внедрения кэша: ускорение отклика системы и снижение нагрузки на основной сервер (базу данных, внешние API).
- При проектировании архитектуры необходимо учитывать риск недоступности кэш-хранилища и обеспечивать возможность работы без него.
- Данные подходят для кеширования только если они редко изменяются (например, справочная информация), тогда как часто меняющиеся данные не следует кэшировать.
- Кэширование часто меняющихся данных может приводить к проблеме N+1 и замедлению работы приложения.
- В кэш нельзя хранить персональные данные пользователей или информацию о финансовых операциях из-за рисков безопасности.
- Стратегия Absolute Expiration удаляет объект через фиксированное время, что подходит для справочников.
- Подход с фоновой записью данных подходит для телеметрии или игровых серверов, но неприемлем для финансов из-за риска потери данных при падении диска.
- Внутренний кэш хранится в оперативной памяти приложения (MemoryCache), но имеет недостатки: холодный старт при перезагрузке и сложность синхронизации при горизонтальном масштабировании.
- Redis предпочтительнее Memcached для внешних кешей благодаря поддержке персистентности, транзакций и кластерных конфигураций.
